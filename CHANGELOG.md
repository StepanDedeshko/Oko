# История изменений Око

## v0.3.3

Крупное обновление Око с улучшениями обновления, графиков, Redmine, переноса настроек и стабильности.

### Главное

- Кнопка “Да” в уведомлении об обновлении теперь сразу открывает раздел “Обновление” и запускает установку.
- Окна проверки графиков теперь можно растягивать мышкой, разворачивать стандартной кнопкой окна и переключать клавишей F11.
- Убрано старое промежуточное окно “Проверка проблем Zabbix”; сценарий сразу открывает графики.
- Добавлена детализация RAM по клику на плашку “Память”.
- Добавлен гибридный режим Redmine для больших описаний.
- Улучшена миграция настроек: шаблоны, ссылки, продукты и страницы, настройки обновления и `zabbix_triggers`.
- Исправлен перенос списка проблем/триггеров Zabbix для фильтров.
- Улучшена первая установка и проверка зависимостей.

### Обновление

- При запуске Око, если найдена новая версия, кнопка “Да” теперь не просто закрывает уведомление, а открывает раздел “Обновление” и сразу запускает скачивание/установку.
- Если нажать “Нет”, обновление не запускается.
- Добавлена защита от двойного запуска обновления.
- Если ссылка обновления отсутствует, Око показывает понятную ошибку.

### Графики

- Окна проверки графиков стали обычными расширяемыми окнами.
- Добавлена кнопка “Развернуть”.
- Добавлена поддержка F11 для переключения размера окна.
- График внутри окна растягивается вместе с окном.
- Окна открываются в удобном размере и не должны уходить за пределы экрана.

### Redmine

- Для большого количества триггеров Око больше не формирует огромную Redmine-ссылку.
- Теперь используется короткая ссылка, а полное описание вставляется в форму Redmine автоматически.
- Если автоподстановка не сработала, описание копируется в буфер обмена.

### Настройки и перенос конфигурации

- Улучшена миграция старых конфигов.
- Добавляются отсутствующие разделы настроек без затирания пользовательских значений.
- Улучшен перенос:
  - шаблонов;
  - ссылок;
  - продуктов и страниц;
  - настроек дежурки;
  - настроек проверки сервисов;
  - списка “Триггеры Zabbix”;
  - фильтров, которые используют список триггеров.

### Память

- Плашка “Память” стала кликабельной.
- В popup показывается общая память и топ процессов по потреблению RAM.
- Popup теперь не уходит за нижний край экрана и имеет прокрутку.

### Стабильность

- Исправлен observer WebView при закрытии duty/OTRS окон.
- Добавлен безопасный cleanup WebEngine при закрытии приложения.
- Убраны предупреждения WebEngine при завершении работы.
- Улучшена очистка WebView, таймеров и фоновых проверок.

### Проверено

- Автоматические тесты: 239 passed.
- Ручной запуск приложения выполнен.
- Проверено закрытие приложения без старых WebEngine warning.
- Проверены окна графиков и popup памяти.

## v0.2.22 Patch 1

Око v0.2.22 Patch 1

Горячий патч для стабильности окна приложения и проверки триггеров дежурства.

Исправлено:
- Исправлена адаптация главного окна Око к разным разрешениям, масштабу интерфейса ОС, DPI и рабочей области монитора.
- Око больше не должно открываться за пределами экрана или под системной панелью.
- Исправлена проблема, из-за которой системные кнопки окна — свернуть и развернуть — могли не реагировать при некоторых разрешениях и масштабе интерфейса.
- Улучшено поведение окна при fullscreen: F11 включает/выключает полноэкранный режим, Esc выходит из fullscreen.
- Улучшены крупные страницы настроек: содержимое должно прокручиваться, а не раздувать окно.
- Исправлены настройки триггеров дежурства: длинные названия продуктов, разделов, метрик и графиков больше не должны растягивать окно.
- Диалоги настроек теперь должны открываться внутри текущего экрана и корректно изменять размер.
- Увеличено ожидание загрузки источника для проверки сработок, чтобы снизить ложные сообщения “Нет данных для проверки сработок”.
- Улучшено логирование проверки триггеров дежурства: теперь проще понять, открылась ли форма логина, не дорисовалась ли таблица, не найден ли заголовок метрики или нет строк данных.

Не включено:
- Музыкальный виджет не входит в этот патч.
- Экспериментальные изменения музыки оставлены в отдельной ветке.

## v0.2.21

Дата: 2026-06-05

### Главное
- Добавлен раздел “Шаблоны”.
- Добавлены редактируемые шаблоны заметок ОТРС.
- Добавлена заготовка шаблонов задач Redmine.
- Оптимизировано потребление памяти при работе с WebEngine-графиками.
- Возвращена кнопка “Обновить” для ручного обновления графиков.

### Шаблоны
- На главной странице добавлен раздел “Шаблоны”.
- Добавлен редактор шаблона заметки ОТРС.
- Добавлен редактор заготовки шаблона задачи Redmine.
- Добавлены кнопки сохранения и сброса шаблонов по умолчанию.
- Добавлен справочник переменных с описаниями и примерами.
- Добавлены примеры Redmine-разметки для изображений и collapse-блоков.
- Добавлено предупреждение, что Redmine-изображение `!filename.png!` будет отображаться только после прикрепления файла к задаче.

### Заметки ОТРС
- Текст заметки при кнопке “Проверено” теперь формируется через шаблон.
- В заметку добавляются статистика проверки, активные триггеры и связанные графики.
- Добавлены переменные `{active_triggers}` и `{active_problems}`.
- Если активных триггеров нет, выводится понятный текст “Не обнаружены”.
- Неизвестные переменные безопасно заменяются пустой строкой.

### Redmine
- Добавлена заготовка шаблона задачи Redmine.
- Добавлены переменные для будущей вставки связанных графиков:
  - `{graph_1_title}`;
  - `{graph_1_url}`;
  - `{graph_1_image}`;
  - `{graph_1_redmine_image}`;
  - `{graph_1_collapsed}`;
  - `{graph_images}`;
  - `{graph_images_collapsed}`;
  - `{screenshots_folder}`.
- Полноценное создание задач Redmine пока не включено, подготовлена только шаблонная база.

### Графики
- На странице Продукт → Графики возвращена кнопка “Обновить”.
- В окне проверки графиков режима дежурства добавлена кнопка “Обновить”.
- Ручное обновление переиспользует существующие WebEngine-карточки и не пересоздаёт графики без необходимости.
- При ручном обновлении сохраняется выбранный период графиков.
- Cache-buster для графиков заменяется корректно и не накапливается в URL.

### Оптимизация памяти
- Добавлен общий helper жизненного цикла WebEngine.
- Добавлена безопасная очистка `QWebEngineView` и `QWebEnginePage`.
- Усилена очистка обычных графиков при переключении разделов.
- Усилена очистка overlay проверки графиков после закрытия.
- Усилена очистка hidden WebView при проверке duty triggers.
- Останавливаются таймеры обновления для скрытых и уничтожаемых страниц.
- Добавлено логирование `Memory status` с RSS, количеством graph cards и tracked WebViews.
- Добавлено предупреждение в логах при высоком потреблении памяти.
- Добавлен cleanup WebEngine-ресурсов при закрытии приложения.

### Известная проблема
- При первом открытии раздела “Графики” некоторые WebEngine-графики всё ещё могут отображаться в стандартной рамке и принимать корректный размер только после смены периода, обновления или повторной отрисовки.
- Исправление этой проблемы отложено, потому что экспериментальная правка ухудшила отображение графиков.
- Проблема будет решаться отдельно.

## v0.2.20

Дата: 2026-06-03

### Главное

* Повышена стабильность проверки триггеров дежурства.
* Возвращён сценарий фиксации проверки графиков через кнопку “Проверено”.

### Режим дежурства

* В overlay-панель проверки графиков добавлена кнопка “Проверено”.
* По кнопке “Проверено” открывается окно заметки к привязанной задаче ОТРС.
* При отсутствии привязанной задачи показывается понятное предупреждение.
* Кнопки “Создать задачу дежурства” и “Привязать задачу” не возвращались на основной рабочий экран.

### Стабильность

* Добавлена защита от повторного запуска проверки триггеров, пока предыдущая проверка ещё выполняется.
* Добавлен cooldown между проверками.
* Добавлен timeout для hidden WebView.
* Улучшена очистка QWebEngineView/QWebEnginePage после проверки.
* Ошибка одного триггера больше не должна валить всю очередь проверки.

### Известная проблема

* При первом открытии раздела “Графики” некоторые WebEngine-графики могут отображаться в стандартной рамке и принимать корректный размер только после смены периода, обновления или повторной отрисовки.
* Проблема известна и будет исправляться отдельно. В `v0.2.20` исправление этой проблемы не включено, чтобы не сломать рабочее отображение графиков.
